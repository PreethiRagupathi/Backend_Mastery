# Day 6 – Integrating Prisma ORM with NestJS and PostgreSQL

## Date
03 August 2026

## Objective

The objective of today's learning was to integrate Prisma ORM into a NestJS application, establish a connection with a PostgreSQL database, define database models using the Prisma schema, generate database tables through migrations, and understand the complete Prisma workflow for database management.

---

# Topics Covered

## Introduction to Prisma ORM

Learned about Prisma as a modern Object Relational Mapper (ORM) that simplifies database interactions by allowing developers to perform database operations using TypeScript instead of writing raw SQL queries. Understood how Prisma acts as a bridge between a NestJS application and a PostgreSQL database while providing type safety and improved developer productivity.

---

## Installing and Configuring Prisma

Installed the required Prisma packages:

- Prisma CLI (`prisma`)
- Prisma Client (`@prisma/client`)

Initialized Prisma in the project, which generated:

- `prisma/schema.prisma`
- `.env`

Configured the PostgreSQL connection by setting the `DATABASE_URL` environment variable and understood the structure of a PostgreSQL connection string, including the username, password, host, port, and database name.

---

## Understanding the Prisma Schema

Explored the structure of the `schema.prisma` file and understood its three major sections:

- Generator
- Datasource
- Model

Learned that:

- **Generator** defines how the Prisma Client is generated.
- **Datasource** specifies the database provider and connection details.
- **Model** represents a database table.

---

## Creating Prisma Models

Created the first Prisma model:

```prisma
model User {
  id   Int    @id @default(autoincrement())
  name String
}
```

Understood the purpose of:

- `model` for creating database tables.
- `Int` and `String` data types.
- `@id` for defining the Primary Key.
- `@default(autoincrement())` for automatically generating unique IDs.

---

## Database Migration

Used Prisma Migrate to generate and apply database migrations.

Learned that migrations:

- Compare the Prisma schema with the database.
- Generate SQL scripts automatically.
- Create or update database tables.
- Maintain migration history.

Successfully generated:

- `User` table
- `_prisma_migrations` table

Verified both tables in pgAdmin after the migration.

---

## Understanding Prisma Commands

Learned the purpose of the following Prisma commands:

- `npm install prisma --save-dev`
- `npm install @prisma/client`
- `npx prisma init`
- `npx prisma db pull`
- `npx prisma migrate dev --name init`
- `npx prisma generate`
- `npx prisma migrate status`
- `npx prisma migrate reset`

Also understood the difference between:

- **`prisma db pull`** – Imports an existing database schema into Prisma.
- **`prisma migrate dev`** – Creates or updates the database from the Prisma schema.

---

## Verifying Database Changes

Verified the migration by inspecting the PostgreSQL database in pgAdmin.

Confirmed that:

- The `User` table was successfully created.
- The `_prisma_migrations` table was automatically generated by Prisma.
- The database schema was synchronized with the Prisma model.
